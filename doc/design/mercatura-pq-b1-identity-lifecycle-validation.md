## D. Identity lifecycle and trust binding

Final real-node V2 execution verified fresh session IDs and both ephemeral
identities after reconnect, persistent identities across restart, explicit
outbound expected pins, wrong-pin disconnect without fallback, and explicit
identity rotation followed by explicit pin update. Unpinned possession reports
authenticated encryption but no verified trusted identity. Inbound endpoints
do not inherit outbound trust assurance.

Four concurrent in-memory sessions share one immutable persistent identity,
produce distinct session IDs and preserve sibling sessions when one pair
disconnects. Cancellation retains an ephemeral identity while its worker owns
it, then releases and wipes it. A fingerprint from a different network fails
before decapsulation; pins do not bypass source admission limits. Concurrent
repeated disconnects release each admission exactly once in the covered case.
Destination spelling remains exact; aliases are not normalized into trust.

## E. Filesystem hardening and recovery

The existing POSIX loader checks the selected parent directory's owner, mode,
type and opened inode/device; uses `O_NOFOLLOW`, descriptor-relative operations,
exclusive random temporary creation, 0600 permissions before secret writes,
file fsync, no-clobber `linkat`, temporary unlink and directory fsync. Loading
rejects symlinks, hardlinks, nonregular files, unsafe owner/mode, wrong size,
magic/version/reserved fields, network/checksum mismatch and seed/public-key
inconsistency. Missing/corrupt identities are not silently regenerated.

B1 injects open/stat/owner/mode/inode failures, interrupted and short I/O,
partial-write failure, read failure, file/directory fsync failure, link failure
and temporary-unlink failure. Tests verify zero tracked descriptor leaks,
cleansed file buffers, no premature final file, and successful explicit retry
where appropriate. Seven synthetic corrupt-file fixtures remain unmodified.
Real-node checks reject invalid paths, malformed pins and duplicate bindings.

A confirmed diagnostic defect concealed failed temporary cleanup behind an
earlier write error. Creation now distinguishes an unpublished failure with a
residual temporary from an already published identity whose cleanup/durability
was not confirmed. It never deletes/replaces the published key. A residual
hardlink remains rejected until the test owner explicitly removes the temporary;
this is evidence of controlled recovery, not automatic operational deletion.

These tests do not simulate a true crash/power loss. The unencrypted seed file
depends on filesystem/user trust; its checksum detects corruption, not a
malicious authorized writer. Same-user/root access and trusted ancestor paths
remain assumptions. Linux POSIX behavior was tested; Windows persistence
continues to fail closed pending owner-only ACL/publication qualification.

## F. Secret lifecycle

The [ownership appendix](mercatura-pq-b1-secret-ownership.md) inventories seeds,
ML-DSA/ML-KEM private keys, signing randomness, coins, shared secrets, IKM, PRK,
confirmation/traffic keys, HMAC temporaries, cipher state and cleanup boundaries.
Move-only `Secret<>` uses `memory_cleanse` and clears moved-from objects.
Identity and packet-cipher copying is prohibited. Successful key transfer,
all five truncated handshake stages, intact-length signature/confirmation
failures, false/throwing RNG, cancellation, timeout, destruction and storage
failure paths are covered by source review and focused tests.

B1 clears old key/signature outputs before a throwing RNG can interrupt
regeneration. Failed worker jobs now discard the handshake, response and their
admission reference before release-publishing completion. Removed queued jobs
receive the same cleanup and a published terminal result even when another
owner retains the `Work` object. Public pin-mismatch classification survives
cleanup without retaining a secret-bearing handshake.

The test interposer calls the real cleanser, then observes storage while it is
still valid; it does not read destroyed/freed objects. Private buffers are
checked with boolean assertions, never dumped. Native implicit rejection for
correct-length invalid KEM ciphertext remains intact. HKDF has fixed valid
production sizes; invalid-size rejection is tested at the wrapper, rather than
inventing an impossible production parameter or changing its algorithm.

Object-level erasure does not prove erasure of all native temporaries, compiler
spills/registers, allocator copies, swap or core dumps. Application plaintext
vectors and physical filesystem deletion have no new secure-erasure guarantee.
Persistent identity owners may intentionally outlive `Stop`; successful
unconsumed results remain owned until transport/caller cleanup.

## G. Worker, cancellation and shutdown

The context owns and joins its two workers; leases own accounting only, never
the worker pool. Transport and worker share a `Work` lifetime, while mutable
handshake state has exclusive ownership. Workers never dereference a transport.
Completion uses release/acquire synchronization. Generation/cancellation checks
reject stale results; disconnect is terminal and repeatable.
Internal callers must submit a fresh job only once and leave its non-atomic
fields exclusively to the worker until acquire-observing completion. Production
worker RNG has no owner callbacks; pool shutdown/destruction occurs on external
owner threads, never through a worker calling `Stop` on itself. These are API
ownership contracts, not enforcement against arbitrary in-process callers.

The new tests hold execution before calculation, after calculation and before
completion publication, including a ready final handshake result. They cover
pending-transport destruction, identity lifetime during cancellation, stale
generation, queued shutdown, worker exception/recovery, partial thread startup
failure at the first/second worker and concurrent `Stop` requests.

Two related shutdown failures were found: a completed unconsumed result could
install keys after `Stop`, and repeated concurrent callers could access/join
the same worker state. A stop mutex now serializes joins; the existing monotonic
stopped quota state gates transport processing and reported assurance. Existing
sessions no longer report authentication or send new packets after shutdown.
The concurrent join test holds the first join and checks serialization; the
unsafe pre-fix double join was not deliberately executed.

Lock review: transport operations take their mutex then quota checks; `Stop`
takes its stop mutex, releases the quota lock, removes/cancels jobs under the
queue lock, releases it, cleans jobs, then joins. Workers do not take the stop
mutex. Lease cleanup is outside the queue lock. No new KEM/signature operation
runs while a networking/chainstate or queue lock is held. Cancellation cannot
interrupt native crypto mid-call; shutdown waits for it to return. TSan covers
the deterministic scenarios, not every possible schedule or uninstrumented code.
