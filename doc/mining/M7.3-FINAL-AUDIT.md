## Corrections

There was no fixed 12-worker ceiling. The audit found three resource-detection
gaps: fixed-size Linux affinity masks could miss restrictions on machines with
large CPU IDs; cgroup detection assumed v2 at `/sys/fs/cgroup`; and the Qt page
cached limits at construction. Linux detection now grows its affinity buffer,
reads process mount/membership metadata, and applies visible v1/v2 ancestor CPU,
cpuset and memory limits, including bind mounts and namespace roots. It also
respects process address-space headroom. Windows detection now considers process
groups, affinity, default CPU sets, job CPU caps and job per-process commit limits.
The Windows detector was cross-compiled and linked with MinGW; its SDK omits the
named min/max-rate fields, so the implementation reads the documented packed ABI.

Qt refreshes resource limits while idle and immediately before Start. Saved values
are read without narrowing to a signed 32-bit integer before clamping. Automatic
resource clamping preserves the saved manual preference. The existing form,
Start/Stop layout, GPU discovery and GPU selection remain intact.

## Formula, inputs and enforcement

Let `C` be the usable logical CPU count after supported OS restrictions, `A` the
minimum available memory/headroom reported by supported sources, and `G` the
number of selected GPU host verifiers. In bytes:

```text
worker budget = 128 MiB private MercaHash scratchpad + 32 MiB overhead = 160 MiB
reserve       = max(512 MiB, floor(A / 4))
memory slots  = floor(max(0, A - reserve) / 160 MiB)
CPU-only max  = min(C, memory slots)
combined max  = min(C, max(0, memory slots - G))
```

Unknown memory permits one host context in total; known insufficient memory
permits none. A compile-time assertion ties the worker budget to the authoritative
scratchpad constant. No CPU model lookup table or arbitrary worker ceiling exists.
The internal unsigned count and Qt's signed integer representation are saturated
before conversion; those representation bounds do not limit real supported machines.

Linux inputs are hardware concurrency, dynamically sized `sched_getaffinity`,
`Cpus_allowed_list`, cgroup cpusets, CPU quotas/periods, `MemAvailable`, remaining
cgroup memory, and finite address-space limits minus `VmSize`. CPU quotas use
`max(1, floor(quota / period))`: one indivisible worker remains possible for a
fractional quota and is throttled by the OS. Windows uses active/process processor
groups, a process affinity mask where meaningful, process default CPU sets, job
CPU rate restrictions, available physical RAM and per-process job commit headroom.
macOS retains logical CPU detection and free/inactive host pages.

`src/mining/worker_limits.cpp` implements `CalculateWorkerLimits`,
`MaximumCpuWorkers` and detection. `MiningController::Run` in
`src/mining/cpu_miner.cpp` independently detects and validates the requested count
and combined host budget before provider creation, worker vector reservation or
scratchpad allocation. Each accepted CPU worker still owns one private context.
`MiningPage::updateStatus` and the Start handler use the same detector/helper,
clamp the selector and disable unavailable selections. Qt persists
`mining/cpuWorkers`; changing resources never starts mining automatically.
The safe maximum remains separate from the user's most efficient operating point.

## Deterministic results

These configurations are simulated; they allocate no real scratchpads.

| Logical CPUs | Available RAM | CPU maximum | With two GPU verifiers |
|---|---|---|---|
| 8 | 256 GiB | 8 | 8 |
| 12 | 256 GiB | 12 | 12 |
| 16 | 256 GiB | 16 | 16 |
| 32 | 256 GiB | 32 | 32 |
| 64 | 256 GiB | 64 | 64 |
| 192 | 256 GiB | 192 | 192 |

Qt independently verifies every corresponding manual selector maximum and value.
At 1 GiB available RAM, 192 logical CPUs permit three CPU workers, two with one
GPU verifier, one with two verifiers, or zero with three. At 8 GiB, the memory
maximum is 38; at 512 MiB it is zero; unknown RAM allows at most one context.
Boundary tests include exactly one worker's budget and one byte below it.

Simulated 192-CPU affinity restricted to four yields four workers. A 12-CPU cpuset
with CPU IDs beyond 1024 remains supported; process affinity restricting it to two
yields two. An ancestor quota of 3.5 CPUs yields three; a 0.5-CPU quota yields one.
Equivalent v1 restrictions and v2 custom/bind/namespace mounts are covered.
One GiB of remaining address space yields three workers. Malformed/overflowing
memory fields fall back to the conservative unknown-memory limit.

Tests cover unsigned-maximum CPU counts and 64-bit memory without overflow or
large allocations. Qt safely clamps a saved unsigned-maximum count to its valid
spinbox representation. A saved 192-worker preference is displayed as four after
an idle resource reduction and as 64 on reopening a simulated 64-CPU machine;
an explicit subsequent selection of seven persists on reopening. Backend fixtures
launch exactly four mocked workers, reject four after resources reduce to two
before another allocation, then launch exactly two. Existing twelve-worker,
partial-start failure, restart/cleanup and combined CPU/GPU tests remain passing.
