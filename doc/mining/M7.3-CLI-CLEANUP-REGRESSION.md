## Reindex and callback repairs

Normal RPC startup retains its existing timeout. Only this reindex test separates
RPC readiness from import completion using `wait_for_import=False`. The subsequent
import must finish within 300 seconds, matching the existing bounded 102-block
native Solo qualification. Height must never decrease or exceed the original
height. A 60-second interval without height progress still fails; after the final
height it must also finish loading the mempool. All original tip, height, balance,
ownership and post-reindex spend assertions remain. No global timeout multiplier,
production validation change or bypass is introduced.

The send/receive failure was a measured callback race: the receiver's pending
balance was queried at `12:20:04.898905`, and its queued `AddToWallet` callback ran
at `12:20:04.900359`. The existing queue-drain RPC provides the required barrier;
the `1.00 MCA` assertions remain exact. This extends the same correct synchronization
already used by the M7.3 batching test.

The second complete run exposed the equivalent race after peer admission. The
native pending-balance audit found six more fixtures relying on admission or
reorganization rather than callback completion: coinbase maturity, many-input
selection, PSBT, mempool persistence, malformed-P2P acceptance and reorganization.
Only the missing receiver-node queue barriers were added at those exact checks.
The framework's existing `sync_mempools` already has the same barrier; no helper,
amount assertion or production wallet behavior was weakened.

One targeted rerun encountered a separate harness port collision: concurrently
started one-test runners both used RPC port 16000 and returned `Unable to start
HTTP server`. Rerunning them sequentially resolved it. The final full suite uses
`TEST_RUNNER_PORT_MIN=21000` and is the only active functional harness. This is an
orchestration issue, not an application source defect.
