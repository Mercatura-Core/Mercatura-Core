## Implemented changes

`difficulty.cpp/.h` keeps one bounded accepted-work observation per connected
session. `GetJob` computes a next target and commits it with that job and the
existing session target row. Neither old jobs nor shares change. No schema
version/account lifecycle migration or new network messages are introduced.

`service.cpp` adds service-level concurrent admission checks, pending block byte
admission, overload accounting, retryable queued replay, latched accounting and
verification failures, and explicit temporary-unavailability submission errors.
`ledger.cpp` adds indexes for recent work, per-session jobs and candidate scans.
Newly discovered network candidates precede a bounded reconciliation history walk.

The native Qt client preserves a failed submission on 112 and pauses mining
while reconnecting. UI widgets, navigation, payout settings and independent-pool
support are unchanged. CPU/GPU and Solo controller code is unchanged.

## Difficulty algorithm and defaults

| Setting | Default |
|---|---|
| VarDiff | Enabled |
| Initial target | `003fffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff` |
| Initial expected work / share probability | 1,024 / 1 in 1,024 |
| Hardest operator target | 1, encoded in 64 hex digits |
| Easiest operator target | `0fffffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff` (score 16) |
| Desired share interval | 150 s (configurable 30–3,600 s) |
| Early observation | At least 60 s and four accepted shares |
| Full/no-share observation | 600 s |
| Verifier workers / queue / configured hash RAM | 1 / 16 / 160 MiB |
| Pending serialized-block budget | 64 MiB |
| Reconciliation batch | 16 candidate visits |

For committed accepted work `W`, elapsed served time `E`, current score `S` and
desired interval `I`, compute `A=floor(W*I/E)`. Apply 25% hysteresis, 50%
smoothing, bounded score arithmetic, upward-rounded target denominators and
exact target-space bounds to prevent more than a twofold expected-work change.
Then apply operator bounds and the network floor. Network changes/operator
bounds can override the gradual step. See [coordinator documentation](../pool-coordinator.md#m71-bounded-share-difficulty)
for the complete integer formula and configuration constraints.

Only successfully committed work contributes; neither client hashrate nor
claimed difficulty is accepted. Full-width arithmetic covers 257-bit work and
observation totals under 287 bits and estimator intermediates under 300 bits. Division/target conversions are checked.
There is one observation, not a history-sized estimator buffer.

No-share/no-hash windows ease conservatively to the configured bound. Slow miners
can require several windows to ramp down. Reconnect/restart preserve the durable
target and restart observations; offline time cannot ease work. Expired work gaps,
RPC recovery and exceptionally long stalls reset observations. Normal tip changes
preserve continuously served observations. Overload-biased windows cannot ease;
they can harden from accepted work. Hostile invalid-nonce demand is still subject
to resource and admission limits, rather than being regulated by accepted-work
VarDiff. Normal target intervals are statistical goals, not delivery guarantees.

## Protocol compatibility

Protocol, algorithm, accounting and snapshot versions remain 1. No fields are
added to hello/job/manifest/receipts. Existing M4 clients consume varied targets,
validate PQ coinbases/payout conservation and check receipt scores against each
issued job. The server reconstructs durable job commitments from the exact
stored target and frozen snapshot; the client treats job IDs as opaque because
v1 lacks issuance time for independent ID recomputation. It refuses a changed
message under the same job ID. This remains authenticated centralized accounting,
not an operator-signed or decentralized proof of the complete share ledger.

Queued replay returns 110 rather than a receipt-less 108. Accepted replay still
returns its original 108 receipt. Updated Qt additionally preserves 112 submissions;
older clients should be upgraded for that recovery improvement. A stale retry can
still lose eligibility. Operator configs with an initial target outside enabled
VarDiff bounds fail startup explicitly; review bounds or select fixed mode.
Fixed regtest fixtures explicitly opt out. Resumed legacy easy targets are bounded
on the next issued job; existing job targets are never retroactively rewritten.

## Payout, identity and consensus invariants

* Frozen MercaHash V1, private 128 MiB scratchpads, 131,072 mixing steps,
  authoritative CPU rehash of GPU solutions, 150-second timing/DGWv3/SP-LT,
  ML-DSA-65 and native witness-v2 payouts are unchanged.
* Every share uses `floor(2^256/(issued_target+1))`; old-job and mixed-target
  PPLNS weights are exact under the existing accounting rule.
* Payout scripts stay bound to the durable session/identity. Cross-session work,
  substituted scripts, non-PQ addresses and forged work/difficulty are rejected.
  Registration chooses a public payout address; it is not ownership proof.
* Largest-remainder allocation conserves every base unit, including 2-decimal
  monetary rounding. Zero allocations stay auditable and have no spendable output.
* Positive outputs are direct coinbase PQ payments. Fees remain 0%; there are no
  custodial balances, claims, withdrawal schedules or donation deductions.
* 1,000 lifetime payout identities, current registration quotas, output capacity
  reservation and historical eligibility remain intact. No retirement is added.
* Jobs commit before issuance. Share/candidate commit is atomic before ACK or
  submitblock; UNIQUE work IDs prevent double credit. Frozen snapshots and
  historical shares are not modified after target changes or restarts.

## Overload, cancellation and recovery

Each verifier preallocates/reuses one 128 MiB scratchpad; M2 detection and 160 MiB
per-worker configuration checks remain enforced. Queues and two-pending/session
limits stay bounded, including resume with pending old-connection work. Pending
block bytes add a separate budget; this is conservative serialized-byte accounting,
not a complete process RSS cap. Current jobs, transient JSON, TLS/output buffers,
allocator overhead and node resources require additional headroom.

Queue/session/byte saturation returns explicit 110, writes no accepted credit,
and increments overload diagnostics. A pending duplicate remains retryable until
its receipt exists. Reconnect never receives old connection request IDs; it
retrieves durable receipts by replay. Shutdown cancels queued requests, joins
running hashes and resolves promises; interrupted requests are retryable at restart.

SQL failures and invalid durable job/session/share data pause further issuance/acceptance until inspection, recovery
and restart. Aborted transactions have no successful ACK. A healthy RPC cannot
clear the latch. RPC outage pauses work and returns retryable unavailability;
recovery preserves accepted work and resumes normal operation. Failed candidate reconciliation also pauses issuance until a
successful reconciliation, rather than being cleared by template polling.
Disconnect/shutdown skip nonessential metadata writes after storage failure and
still join workers. Candidate discovery
is committed before RPC and retried after a crash. Recent discovered candidates
precede retained history; hash status remains unknown before CPU verification,
so a supposed candidate cannot bypass a full queue safely.

Rejected work can lose PPLNS eligibility if retries expire, tips change or
bounded retries run out. The saturation benchmark measured this loss explicitly.
Do not treat refusal as harmless. Neither VarDiff nor bounded buffers guarantees
availability against distributed invalid-nonce traffic. Retained audit history
uses disk; there is no automatic historical job/session/share pruning.

## Limitations and next milestone

Hardware/remote deployment gaps: no actual NVIDIA or AMD runtime execution;
no Hostinger KVM 4/KVM 8 deployment or WAN TLS qualification. GPU software and
compiler CI evidence is distinct from hardware validation. This Linux environment
has no CUDA/OpenCL toolchain, so that compile matrix relies on fresh remote CI.

Remaining engineering limits include synchronous per-call RPC pauses, cumulative
candidate-batch latency, retained disk history, opaque v1 job IDs, statistical
VarDiff variance and slow-start ramping, initial fast-miner bursts, public-address
registration/Sybil exhaustion, and candidate starvation when the verifier queue
is already saturated. Component budgets do not replace a supervisor RSS limit.

Next: a controlled conventional-pool public-testnet qualification milestone.
Benchmark the actual VPS, intended Core/TLS/storage configuration and bounded
miner cohort; test sustained operation, independent clients, backups/restores,
latency, saturation and native NVIDIA/AMD devices. Use those measurements to
choose operator bounds/budgets and determine whether asynchronous RPC or additional
abuse controls are justified. Keep P2Pool and identity retirement deferred.
