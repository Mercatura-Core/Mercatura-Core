# M7.3 manual Solo Mining qualification

Use a separate candidate build and temporary datadir. Preserve the known-good
M7.2 build, wallet, testnet datadir, and all public infrastructure. Never use a
production wallet for automated tests. Automated validation is documented in
[the M7.3 handoff](M7.3-SOLO-REFINEMENT.md).

Allow 20–40 minutes for interactive CPU checks. A fresh `-j4` build typically
takes 15–45 minutes, and cached incremental builds 2–10 minutes. Real GPU smoke
and vector tests typically need 5–15 minutes per card, depending on hash latency.
No finite public-testnet block-discovery time is guaranteed.

1. Open an isolated regtest wallet. Confirm reopening the wallet does not start
   mining. Confirm no Pool mode selector or Automatic CPU checkbox.
2. On Ryzen 5 4600G, confirm 12 logical workers are selectable when memory and
   affinity permit. Choose a lower count, reopen the page/application and confirm
   persistence. Change available resources and confirm valid clamping/safe failure.
3. Start CPU mining. Check 10-second, 60-second, session-average H/s, hashes and
   Session Runtime. Wait over a minute and verify smooth rates. Stop and confirm
   runtime/hashes freeze after cleanup. Restart and confirm a new session.
4. Copy the PQ reward address and use Show in address book. Confirm the selected
   receiving-address row is the same owned address. Receive payment requests need
   not show it. Enable privacy and confirm address actions are disabled.
5. Repeat with an encrypted wallet, including first address creation, locked reuse,
   label edits, unload/reload, restart and application shutdown while hashing.
   Confirm no unnecessary new reward address and safe relocking/cleanup.
6. Check the pickaxe at 100%, 150% and 200% display scaling, switch light/dark
   palettes while running, and confirm icon refresh and readable page layout.
7. On compatible NVIDIA CUDA and AMD OpenCL hardware, run the frozen MercaHash
   vectors first, then GPU-only and CPU + GPU mining. Check device selection,
   automatic discovery, per-device rates, cumulative combined hashes, cancellation,
   device loss/recovery, memory pressure and clean shutdown.

Record OS, compiler, Qt/driver version, GPU model, workers/contexts, actual
validation and failures. Compilation or controller mocks must never be reported
as physical GPU qualification. CPU throughput comparisons should use sequential
bounded runs on the same quiet host; do not infer energy efficiency from elapsed
time or hashrate alone.
